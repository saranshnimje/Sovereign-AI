## Pre-Demo Checklist

Run this 15 minutes before the demo.

```bash
# 1. Check Docker is running
docker info

# 2. Check Ollama is running and models are loaded
ollama list
# Expected output: llama3.2:3b and nomic-embed-text

# 3. If models not present, pull them (requires internet, ~2GB total)
ollama pull llama3.2:3b
ollama pull nomic-embed-text

# 4. Start Ollama (if not already running as a service)
ollama serve &

# 5. Start the stack
docker compose up --build -d

# 6. Wait ~60 seconds, then check health
curl http://localhost/api/v1/system/health
# Expected: {"status":"ok"}

# 7. Open browser
open http://localhost   # or navigate manually
```

## Demo Workflow D — Document Upload & Knowledge Base

**Narrative:** "We upload a confidential document. It never leaves this machine."

1. Click **Knowledge Bases** in sidebar
2. Click **+ New Knowledge Base** → name it "Policy Documents"
3. Click **📄 Upload Document**
4. Upload a PDF (prepare a small PDF, e.g. a 2–3 page policy document)
5. Enable **Run OCR** (for scanned documents)
6. Click **Process Now**
7. Watch the processing steps update in real time:
   - ✓ Validation → ✓ Extraction → ✓ OCR → ✓ Chunking → ✓ Embedding → ✓ Indexed
8. When complete: "The document has been chunked into N sections, embedded using nomic-embed-text running locally, and stored in a local Qdrant vector database."

**Key point:** "At no point did this document touch the internet."

## Demo Workflow H — Human Approval Gate

**Narrative:** "High-risk operations require explicit human approval. The agent cannot proceed until an admin decides."

**Setup:** Start an agent with a goal that triggers a high-risk tool.

1. Start agent with goal: `"Delete the file named old_data.txt from the workspace"`
2. Watch the execution trace — agent proposes `file_delete`
3. **⚠️ APPROVAL REQUIRED** banner appears
4. Note the **Approvals sidebar badge** shows count = 1
5. Navigate to **Approvals** page
6. See the pending request with:
   - Tool: `file_delete`
   - Risk: **HIGH**
   - File path shown explicitly
7. Add a decision note and click **Approve** (or **Reject**)
8. Switch back to Agents — execution continues (or stops gracefully if rejected)

**Key points:**
- "The agent is completely paused until a human decides"
- "Approval expires after 5 minutes — auto-rejects, never auto-approves"
- "Everything is logged to the immutable audit trail"

## Talking Points for SIH Evaluation

### Why This Architecture?

**Data Sovereignty:** Government, defence, and healthcare organisations cannot send sensitive documents to OpenAI or any cloud AI provider. This system never makes such calls.

**Auditability:** Every AI decision, every tool call, every approval, every login — permanently recorded with cryptographic integrity verification.

**Control:** The AI cannot take unilateral actions on systems. The chain `LLM → Registry → Policy → Approval → Sandbox → Audit` ensures humans remain in control.

**Offline Capable:** After the initial model download (~2GB), the entire system operates with no internet connection. Suitable for air-gapped environments.

**Open Source Models:** Uses open-weight models (Llama, Mistral, etc.) — no vendor lock-in, no per-token cost, full transparency.

## Troubleshooting During Demo

| Symptom | Quick Fix |
|---|---|
| Ollama shows offline | Run `ollama serve` in terminal |

`qwen3:14b` is a **thinking model** — it produces high-quality reasoned answers but needs
~90–230 seconds on CPU. For a 10-minute demo, plan:

- **Show retrieval first** (instant results, excellent for demoing semantic search)

`qwen3:14b` should be kept as the **primary showcased model** (better quality, shows
the system works with large thinking models).
